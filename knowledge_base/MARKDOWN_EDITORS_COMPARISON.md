## 1. marka.md — AI上下文管理专用编辑器

### 基本信息
- **GitHub**: https://github.com/mattenarle10/markamd
- **Stars**: ~500+ (快速增长中，4个月55个版本)
- **技术栈**: Tauri 2 + React + TypeScript
- **平台**: macOS / Windows / Linux
- **许可证**: MIT
- **官网**: https://markamd.vercel.app

### 核心功能

#### 1. Context Tray（上下文托盘）— 差异化卖点
| 功能 | 说明 |
|-----|------|
| **文件暂存** | 将多个.md文件拖入侧边栏暂存区 |
| **Token计数** | 实时显示每个文件和总token数 |
| **一键复制** | 将所有暂存文件内容拼成完整文本块，直接进剪贴板 |
| **相对路径标注** | 粘贴到AI时自动标注来源文件路径 |

**解决什么问题**：
- 过去：逐个打开文件→全选复制→拼到临时文件→再复制给AI
- 现在：拖进去→点复制→粘贴给AI，两步完成

#### 2. 编辑器基础功能
| 功能 | 实现 |
|-----|------|
| **实时预览** | 左右分栏，左边写右边渲染 |
| **代码高亮** | Shiki引擎，支持多种语言 |
| **Mermaid图表** | 流程图、时序图、甘特图 |
| **CSV预览** | 直接渲染表格，无需Excel |
| **三种视图** | 双栏编辑/纯阅读/纯编辑器 |
| **Vim模式** | 可选开启 |
| **主题系统** | 分组主题+透明度调节 |

#### 3. 文件管理
| 功能 | 说明 |
|-----|------|
| 文件夹树 | 左侧目录导航 |
| 标签页 | 多文件同时编辑 |
| 收藏 | 常用文件置顶 |
| 搜索 | ⌘K命令面板 |
| 拖拽移动 | 文件重新组织 |

### 优势与劣势

| 优势 | 劣势 |
|-----|------|
| 极小包体积(8-12MB) | 仅支持.md文件，无Wiki格式 |
| Context Tray解决AI搬运痛点 | 功能尚不成熟，迭代快bug多 |
| 完全本地，无遥测无账号 | PDF导出依赖系统打印，非原生 |
| 更新频率极高(2.5天一版) | Windows版无代码签名，SmartScreen报警 |
| Linux支持Deb/RPM/AppImage | 社区规模小，文档有限 |
| MIT开源，可二次开发 | 暂无移动端 |

### 适用场景
- ✅ 技术文档维护者（多文件上下文整合）
- ✅ AI工作者（频繁喂context给Claude/Codex）
- ✅ 隐私敏感用户（本地优先）
- ❌ 重度笔记管理（不如Obsidian）
- ❌ 复杂排版需求（不如Typora）
- ❌ 团队协作（无云同步）

## 4. 技术架构对比

### 4.1 技术栈

| 编辑器 | 前端框架 | 后端/运行时 | 语言 |
|-------|---------|------------|------|
| **marka.md** | React + TypeScript | Tauri 2 (Rust) | Rust + TS |
| **Typora** | Electron | Node.js | JavaScript |
| **MarkText** | React + TypeScript | Electron | TypeScript |
| **Obsidian** | React + TypeScript | Electron | TypeScript |
| **VS Code** | React + TypeScript | Electron (Monaco) | TypeScript |

### 4.2 性能对比分析

**Tauri vs Electron**:
| 维度 | Tauri (marka.md) | Electron (其他) |
|-----|------------------|-----------------|
| **内存占用** | 低（共享系统WebView） | 高（每个窗口独立进程） |
| **安装包** | 小（~8-12MB） | 大（~150-300MB） |
| **启动速度** | 快 | 较慢 |
| **系统资源** | 轻量 | 较重 |
| **生态成熟度** | 较新（2024年Tauri 2.0） | 成熟稳定 |

**结论**：marka.md在性能和体积上有明显优势，但Tauri生态仍在发展中。

## 7. 项目评价与建议

### 7.1 marka.md评价

**优点**：
1. **精准定位**：解决了AI工作者反复搬运多文件context的痛点
2. **技术选型合理**：Tauri带来性能优势，包体积小
3. **隐私友好**：无遥测、无账号、完全本地
4. **迭代速度快**：作者活跃，响应迅速
5. **免费开源**：MIT许可，可商用可修改

**不足**：
1. **功能尚不完善**：PDF导出依赖系统打印，无原生支持
2. **社区规模小**：用户基数小，插件生态未形成
3. **稳定性待验证**：高频迭代可能引入bug
4. **Windows体验**：无代码签名，SmartScreen报警
5. **无移动端**：只能桌面使用

### 7.2 与用户本地项目的对比思路

当用户提到"我们本地的MD编辑器一塌糊涂"时，可从以下维度对比：

| 对比维度 | 问题点 | 改进方向 |
|---------|--------|---------|
| **定位清晰度** | 是否明确解决什么痛点？ | marka.md明确解决AI context搬运 |
| **核心功能聚焦** | 是否什么都想做？ | 先做好Context Tray这类差异化功能 |
| **性能优化** | 包体积、启动速度 | Tauri架构优于Electron |
| **用户流程** | AI上下文打包是否顺畅？ | 参考marka.md的两步操作设计 |
| **隐私保护** | 是否有遥测/账号依赖？ | 本地优先，无数据上报 |
